# Deployment Guide: Spovishun Bot on Oracle Cloud VM

## Інфраструктура

| Компонент       | Значення                                      |
|-----------------|-----------------------------------------------|
| Провайдер       | Oracle Cloud Free Tier                        |
| VM Shape        | VM.Standard.E2.1.Micro (x86, 1 OCPU, 1 GB RAM)|
| ОС              | Ubuntu 22.04 LTS                              |
| IP сервера      | 141.147.4.30                                  |
| Docker образ    | ghcr.io/astrumon/spovishun:latest             |
| Registry        | GitHub Container Registry (ghcr.io)           |
| База даних      | Neon Cloud PostgreSQL (prod profile)          |
| SSH user        | ubuntu                                        |

---

## Чому саме такий підхід

Oracle Free Tier надає ARM VM (A1.Flex, 4 OCPU / 24 GB RAM безкоштовно), але на момент
налаштування всі ARM capacity були вичерпані. Обрано x86 E2.1.Micro як fallback.

У E2.1.Micro лише 1 GB RAM — недостатньо для `./gradlew installDist` усередині Docker build.
Тому обрано схему: збирати образ локально → пушити на ghcr.io → сервер тільки пулить і запускає.

## Кроки, які були зроблені (одноразово)

### 1. Створення VM на Oracle Cloud

1. Oracle Cloud Console → Compute → Instances → Create Instance
2. Image: Ubuntu 22.04 (Canonical)
3. Shape: VM.Standard.E2.1.Micro (x86)
   - Увага: доступний лише в одному AD (AD-2) — вибирати його
4. SSH Keys: завантажити свій публічний ключ або згенерувати новий
5. Networking: при створенні увімкнути "Assign a public IPv4 address"
   - Якщо кнопка заблокована — після створення вручну: VNIC → IP addresses → Edit → Ephemeral IP
6. Після запуску VM: Networking → Connect public subnet to internet (додає Internet Gateway)

### 2. Підключення до сервера

```bash
ssh -i ~/.ssh/oracle_key ubuntu@141.147.4.30
```

### 3. Встановлення Docker на сервері

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y docker.io docker-compose-v2
sudo usermod -aG docker $USER
exit
# SSH знову — для застосування групи docker
```

Перевірка:
```bash
docker --version
docker compose version
```

### 4. Клонування репозиторію на сервер

```bash
git clone https://github.com/Astrumon/Spovishun.git
cd Spovishun
```

Якщо репозиторій приватний — використати GitHub PAT:
```bash
git clone https://Astrumon:<PAT_TOKEN>@github.com/Astrumon/Spovishun.git
```

### 5. Створення .env файлу на сервері

```bash
nano .env
```

Вміст (реальні значення):
```
TELEGRAM_BOT_TOKEN=<токен від BotFather>
ADMINS=<telegram user id через кому>
PROFILE=prod
PROD_DATABASE_URL=jdbc:postgresql://ep-xxx.region.aws.neon.tech/neondb?sslmode=require
PROD_DATABASE_DRIVER=org.postgresql.Driver
PROD_DATABASE_USERNAME=neondb_owner
PROD_DATABASE_PASSWORD=<пароль від Neon>
PROD_DATABASE_POOL_SIZE=5
```

DEV_* змінні не потрібні для prod.

### 6. Модифікація docker-compose.yml на сервері

Замінити `build: .` на `image: ghcr.io/astrumon/spovishun:latest`.
Прибрати DEV env overrides та depends_on.

Фінальний вигляд:
```yaml
services:
  bot:
    image: ghcr.io/astrumon/spovishun:latest
    container_name: spovishun-bot
    env_file: .env
    restart: unless-stopped

  postgres:
    image: postgres:16-alpine
    container_name: spovishun-db
    profiles: ["dev"]
    environment:
      POSTGRES_DB: spovishun_dev
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${DEV_DATABASE_PASSWORD}
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d spovishun_dev"]
      interval: 5s
      timeout: 3s
      retries: 5

volumes:
  pgdata:
```

### 7. Налаштування GitHub Container Registry

На локальній машині (Windows):

1. Створити GitHub PAT: Settings → Developer settings → Personal access tokens → Fine-grained або Classic
   - Scopes: `write:packages`, `read:packages`, `delete:packages`
2. Залогінитись:
   ```bash
   echo <PAT> | docker login ghcr.io -u astrumon --password-stdin
   ```

### 8. Збірка та публікація образу (локально)

```bash
# В корені проекту на локальній машині
docker build -t ghcr.io/astrumon/spovishun:latest .
docker push ghcr.io/astrumon/spovishun:latest
```

Увага: назва образу має бути lowercase (ghcr.io вимагає).

### 9. Логін у ghcr.io на сервері та запуск

```bash
# На сервері
echo <PAT> | docker login ghcr.io -u astrumon --password-stdin
docker compose up -d
```

## Оновлення бота (деплой нової версії)

### Автоматичний деплой (CI/CD) — стандартний шлях

Деплой відбувається автоматично при мерджі PR у `main` через GitHub Actions.

Workflow: `.github/workflows/deploy.yml`

**Що відбувається автоматично:**
1. GitHub Actions збирає Docker образ (`./gradlew installDist` усередині Dockerfile)
2. Пушить два теги: `latest` та `sha-<short-sha>` на `ghcr.io/astrumon/spovishun`
3. SSHиться на Oracle VM і виконує `docker compose pull bot && docker compose up -d`

**Необхідні секрети репозиторію** (GitHub → Settings → Secrets and variables → Actions):

| Secret        | Значення                                  |
|---------------|-------------------------------------------|
| ORACLE_HOST   | Публічний IP VM (`141.147.4.30`)          |
| ORACLE_USER   | SSH user (`ubuntu`)                       |
| ORACLE_SSH_KEY| Вміст приватного SSH ключа (PEM формат)   |

`GITHUB_TOKEN` надається автоматично — додаткових секретів для ghcr.io не потрібно.

**Перевірка після деплою:**

```bash
# Подивитись прогрес у GitHub Actions tab
# Або перевірити на сервері:
ssh -i ~/.ssh/oracle_key ubuntu@141.147.4.30
docker compose logs --tail=50 bot
```

Шукати рядки:
- `Bot started successfully` — бот підключився
- `Schema "public" is up to date` або `Applied X migration(s)` — Flyway відпрацював

**Ручний запуск** (повторний деплой без нового PR): GitHub → Actions → Deploy → Run workflow.

---

### Ручний деплой (fallback / перше налаштування)

Якщо GitHub Actions недоступний або потрібно задеплоїти вручну:

#### Крок 1: Локально — зібрати та запушити новий образ

```bash
# В корені проекту на локальній машині
docker build -t ghcr.io/astrumon/spovishun:latest .
docker push ghcr.io/astrumon/spovishun:latest
```

#### Крок 2: На сервері — стягнути та перезапустити

```bash
ssh -i ~/.ssh/oracle_key ubuntu@141.147.4.30
cd ~/Spovishun
docker compose pull bot
docker compose up -d
```

`docker compose up -d` автоматично замінює контейнер на новий образ.
Downtime: ~2-5 секунд.

#### Відкат до попередньої версії

```bash
# sha-<short-sha> доступний як тег у ghcr.io (кожен деплой зберігає sha-тег)
docker pull ghcr.io/astrumon/spovishun:sha-<попередній-sha>
docker tag ghcr.io/astrumon/spovishun:sha-<попередній-sha> ghcr.io/astrumon/spovishun:latest
docker compose up -d
```

## Troubleshooting

### Бот не відповідає

```bash
docker compose ps                  # перевірити що контейнер Up
docker compose logs --tail=50 bot  # шукати ERROR або WARN
```

### Контейнер падає одразу після старту

```bash
docker compose logs bot  # подивитись причину (зазвичай неправильний .env)
```

Найчастіші причини:
- Неправильний `TELEGRAM_BOT_TOKEN`
- Неправильні `PROD_DATABASE_*` credentials
- Neon DB недоступна (перевірити статус на neon.tech)

### Немає місця на диску

```bash
df -h                         # перевірити диск
docker system prune -f        # видалити невикористовувані образи/контейнери
```

### Оновити docker-compose.yml на сервері

```bash
cd ~/Spovishun
git pull  # якщо зміни запушені в репо
# або редагувати вручну: nano docker-compose.yml
docker compose up -d
```

|---------------------------|-------------------------------------|
| `~/Spovishun/.env`        | Секрети і конфіг (НЕ в git)         |
| `~/Spovishun/docker-compose.yml` | Конфіг контейнерів           |
| `/var/lib/docker/`        | Docker дані (образи, volumes)       |

---

## Важливо: чого НЕ робити

- Не комітити `.env` в git — містить секрети
- Не запускати `docker build` на сервері — 1 GB RAM не вистачить
- Не видаляти `~/Spovishun/.env` без backup — доведеться вводити всі секрети знову
- Не змінювати `PROFILE` на `dev` в prod `.env` — підніме локальний postgres замість Neon
